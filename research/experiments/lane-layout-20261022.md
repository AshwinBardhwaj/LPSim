# Physical lane-order layout experiment

Change the records received by motion workers: gather full Car records in (road, lane, position, stable ID) order, remap leader references, build connector/context indexes against that layout, run the unmodified motion kernel, and scatter results to stable-ID order before unchanged junction arbitration. Preserve all pending/stopped/connector/completed records. The fixed 128-thread launch and calculations remain identical. This is a motion-stage layout adapter, not a persistent full-simulator storage redesign.

Compare current radix-indexed storage, lane layout charging all pack/remap/unpack work every step, and an optimistic supplied-input layout (pack/remap excluded, unpack and every other stage charged). The supplied case reuses an immutable snapshot: it is not evidence that a layout can be maintained for free across evolving timesteps. Sorting/index construction and unchanged stages remain in complete pipeline time. Allocation is one-time; all recurring copies and reference maintenance are charged in the practical case. No transfer to CPU in timed intervals.

Use all 36 frozen Berkeley windows: distributed, concentrated and bursty demand; 2,048/8,192/16,384 requested vehicles; t=60/180/300/450 s. Three process repetitions, three warmups and ten randomized repetitions per variant. Exact canonical-ID motion/final Car bytes and reservation summaries must match. Keep earlier milestones unchanged.

Decision gate set before results: pursue a selector only if there is a repeatable >=5% complete replayed-step gain in a meaningful workload subset after all recurring layout costs. A predictor must subsequently beat always-current, always-lane and a cheap current-state rule on held-out demand/networks, including prediction cost. Reserve bursty demand as held-out for any rule fitted using distributed/concentrated cases. No predictor benefit is inferred from sorting or an optimistic supplied-layout win alone. Motion grouping and physical locality both change here; causal separation would require an additional dispatch-only control if the practical gate passes.

Implementation refinement: the first diagnostic used one thread to copy each whole record. Its high copy cost motivated a second adapter with contiguous 32-bit field copies distributed across threads. Preserve both, but use the coalesced adapter for the final matrix. The original gate and workload holdout remain unchanged. No production simulator code is modified.
