# Exact request gating and guarded multi-rate experiment

Frozen reference: compact motion commit 89cb7c2, Berkeley nine 600-second scenarios (three demand patterns × 2,048 / 8,192 / 16,384 requests), dt=0.25 s, identical routes/departures/seed/controller. Production code remains unchanged.

1. Exact inactive-work gating: compare current N-record request sorting with (a) current-state request-key compaction then sort only valid requests, and (b) offline-known two-second unions of potentially eligible vehicle IDs. Oracle evaluates those candidates at the actual current state, keeps invalid sentinel keys, preserves stable arbitration order and downstream/conflict protection. It skips request evaluations and sort padding, not car-following. Scheduled departures and connectors remain fully processed. This is a candidate oracle for this particular gate, not a bound on all regional skipping. Its preparation time and transfers are recorded. Compare oracle against inexpensive current-state compaction, not just the baseline.

2. Multi-rate acceleration: recompute every two/four base steps only for isolated road-interior vehicles without a road leader or incoming-lane connector and with a conservative road-end margin. Recheck eligibility every base step and immediately resume original equations when interaction appears. Hold acceleration, retain 0.25-second trapezoidal integration, motion bounds, index construction and junction updates. These approximate variants may change trajectories. This is an initial guarded decision-frequency experiment, not unconstrained regional time skipping.

Validation: all nine full trajectories per variant; exact hashes for gating against reference states/events/signals/timeseries/snapshots; numerical/route-state differences and completion counts for approximate variants; existing gap/conflict/nonfinite/connector-stop checks every step. Diagnostic boundary gap checks use lane extrema rather than a quadratic connector×road-vehicle scan; zero-failure criteria are unchanged. Count reused acceleration updates only in separate instrumented validation runs.

Timing: separate non-instrumented full-horizon runs, one warmup and at least three shuffled process repeats. Timed simulation loop excludes trajectory output and CPU diagnostics; process elapsed includes loading/setup. Charge oracle mask transfers in loop, report offline trace/mask construction separately. Require >=20% net speedup in each repeat for the ambitious structural gate; smaller gains remain reported. No prior is trained unless an opportunity exists beyond the current-state alternative. No new Nsight claims from timing alone.
