# A100 study, 2026-10-28

Budget: $10 total new Modal compute, including failed attempts. Single-use containers, one at a time. Public 40GB GPU rate $0.000583/GPU/s; reserve using 80GB rate $0.000694/GPU/s plus CPU/memory. Stop launching when remaining allowance cannot cover the next bounded run. No learned policy training or held-out tuning.

1. Original physical correctness: 120 steps from the populated 8192-trip historical snapshot, each of three policies, logical and physical devices.
2. Concurrent correctness: the same immutable physics with GPU peer state/ownership/reservation messages, three persistent CPU launch workers, phase barriers. Validate populated 8192/16384 snapshots and fresh bursty demand over 600 s. Compare every timestep with independent original single-GPU state and physical/ghost invariants.
3. Development comparisons: nine training demands, 2048/8192/16384 trips × distributed/concentrated/bursty. Run the common single-GPU prefix 0–180 s, then construct all policies using only the observed 180 s state. This explicitly replaces the frozen empty-state count fallback with real active-count balancing. No future states enter partition construction. Freeze each assignment until 600 s. Primary repeated timing is the 180–600 s continuation, NOT a repeated complete 0–600 s benchmark. Report prefix, assignment construction and initialization separately and add construction/setup for cold costs. This is a development baseline study, not the preregistered held-out 10% success test.
4. One warm-up and five unprofiled repetitions, random policy order seed 2710, same snapshot, exact final-state hashes across all policies/repetitions. Original single-device path uses identical physics and indexes without inter-device barriers. Separate diagnostic repetitions record populations, GPU stage times and snapshots. File serialization excluded from compute wall time and reported separately. Fixed 128-thread launches, dt=0.25 s, original 72 s controller, following enabled, bulk radix indexing. Incremental indexing remains separately available in frozen reference, not combined with policy changes.
5. Nsight Compute measurements collected separately at matched physical times with clock-control none; do not use replay time as runtime. Sample motion and junction arbitration, report GPU identity and per-kernel occupancy, SM throughput, long-scoreboard stalls, eligible warps and active threads. Instrumentation and replay can serialize launches; not evidence of real concurrent occupancy.

Memory is persistent but dense: all partitions reserve N stable-ID vehicle slots and replicate network/routes. Ghost populations, wire/control bytes, active load imbalance and allocated slots are reported. Direct state messages are routed only to destinations; compact ownership changes are broadcast to all partitions. Reservation authority and pre/post-motion exchange ordering are unchanged. Conservative phase barriers deliberately remain. No claim of asynchronous boundary overlap or distributed memory scaling.

Oracle gate: first calculate optimistic savings from perfectly equalizing observed per-device motion/junction stage durations, holding transport unchanged. This is a balance-only opportunity screen, not an optimal partition or proof against communication-aware partitioning. Do not fit a predictor without a measured decision opportunity. Report incomplete experiments and budget-limited coverage explicitly.

Development oracle addendum (before completing the matrix): evaluate a restricted policy-selection oracle candidate. Use only the excluded repeat-0 warm-up time to select one of the three existing peer policies per case; evaluate on repeats 1–5. Report both pre-supplied-choice cost and the cost of running all three calibration trials (compute + setup + assignment construction). This selects among existing assignments; it does not synthesize a measured-cost partition or establish an optimal bound. This exploratory analysis is not the preregistered held-out gate.
